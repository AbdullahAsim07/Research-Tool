# 🦜🔗 LangChain Prompts & Messages: Dynamic Context Engineering

This repository contains the complete, production-grade implementations and exhaustive technical blueprints derived from the **CampusX Generative AI Masterclass (Video 4)** authored by Nitish Singh. This project provides an in-depth breakdown of LangChain's **Prompts and Messages Component**, illustrating how to manage model inputs using robust template abstractions instead of brittle, hardcoded strings.

---

## 🏗️ Architectural Core: Static vs. Dynamic Prompts

In production environments, a **prompt** is the foundational interface payload transmitted to a Language Model (LLM) to guide its generation boundaries. 

*   **Static Prompts (Legacy Pattern):** Hardcoding fixed string queries directly into `.invoke()` calls. This delegates excessive structural risk to end-users, leading to unpredictable token responses, data hallucinations, and inconsistent app behavior.
*   **Dynamic Prompts (Enterprise Standard):** Treating prompts as parameterized functions. Developers pre-configure structurally robust instructions (behavior personas, output targets), exposing strictly bounded template variables where real-time user tokens are injected safely at runtime.

---

## 📊 Technical Deep Dive: LangChain Message Objects

Chat-based architectures require explicit awareness of context origin. LangChain implements distinct object-oriented message components rather than relying on un-serialized dictionaries:

| Message Object Class | Sub-Module Package Path | Structural Purpose & Contextual Behavior |
| :--- | :--- | :--- |
| **`SystemMessage`** | `langchain_core.messages` | Injected at the absolute sequence ceiling to define behavioral personas, rules, and task constraints. |
| **`HumanMessage`** | `langchain_core.messages` | Explicitly wraps the token query submitted by the human client interface. |
| **`AIMessage`** | `langchain_core.messages` | Tracks the corresponding textual payload back-propagation generated by the model. |

---

## 💡 Technical Update: The `temperature` Correction

As clarified by Nitish sir via explicit code logging during this tutorial, the traditional description of `temperature` requires an exact operational update:
*   Setting `temperature=0` forces the sampling architecture to pick the absolute highest probability next-tokens. This ensures **deterministic output invariance**; executing the same input sequence multiple times yields identical results.
*   Scaling `temperature` closer to thresholds like `1.5` or `2.0` introduces diverse token distributions, generating fluid, creative, and completely varied string sequences across identical raw queries.

## 📖 Complete Code Demonstrations

### 🧩 Section 1: Standard PromptTemplate & Local JSON Serialization

#### 1. Dynamic Paper Summarizer Web Interface
This demo uses `streamlit` to build an interface that gathers structured arguments and passes them to a parameterized template.
```python
# 1_PromptTemplates/prompt_ui_app.py
import streamlit as st
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from dotenv import load_dotenv

load_dotenv()

st.header("Enterprise Research Assistant Tool")

# Parameterized Input Extraction
paper_input = st.selectbox("Select Target Research Base:", ["Attention Is All You Need", "Word2Vec", "BERT", "YOLOv10"])
style_input = st.selectbox("Select Explanation Persona:", ["Simple & Intuitive", "Math Heavy", "Code-Oriented Architecture"])
length_input = st.selectbox("Select Target Output Capacity:", ["Short (1 Paragraph)", "Medium (3 Paragraphs)", "Long (Comprehensive Analysis)"])

# Native LangChain PromptTemplate Blueprint Formulation
template_string = """Please summarize the research paper titled: {paper_input}
with the following specific instructions:
- Explanation Style Requirement: {style_input}
- Target Summary Length: {length_input}

Production Constraint Check: Include relevant mathematical equations or code expressions if natively present. If data bounds are missing, respond strictly with 'Insufficient Information Available' to prevent system hallucinations."""

prompt_blueprint = PromptTemplate(
    input_variables=["paper_input", "style_input", "length_input"],
    template=template_string,
    validate_template=True # Raises errors during dev phase if placeholder validation keys mismatch
)

if st.button("Generate Structured Summary"):
    # Formatting placeholder blocks safely via LCEL matching
    formatted_prompt = prompt_blueprint.format(
        paper_input=paper_input, 
        style_input=style_input, 
        length_input=length_input
    )
    
    model = ChatOpenAI(model="gpt-4o-mini", temperature=0.2)
    response = model.invoke(formatted_prompt)
    st.write(response.content)
```

#### 2. Local File System Template Serialization (JSON Storage)
This handles decoupling prompt engineering files from primary execution scripts, allowing multi-page systems to share resources.
```python
# 1_PromptTemplates/prompt_serialize.py
from langchain_core.prompts import PromptTemplate, load_prompt

# 1. Define the base logic engine configuration
template = PromptTemplate.from_template("Analyze the architectural patterns of {framework} in contrast with {library}.")

# 2. Serialize structural configuration details locally into a static JSON node
template.save("template.json")
print("Prompt Template successfully compiled and serialized to local JSON file.")

# 3. Dynamic loading validation loop from outside active file memory bounds
rehydrated_template = load_prompt("template.json")
formatted_output = rehydrated_template.format(framework="Django", library="React")
print(f"Rehydrated Local Target Execution Output:\n{formatted_output}")
```

#### 2. Advanced Multi-Turn Dynamic Templates (The Modern Tuple Protocol)
*Note: Using standard `SystemMessage` classes inside structured lists may fail to bind parameters cleanly with older pipeline architectures. The modern standard uses precise **Role-String Tuples** `(role, template)` to process runtime variables reliably.*
```python
# 2_ChatPromptTemplates/chat_template_pipeline.py
from langchain_core.prompts import ChatPromptTemplate

# Defining modern enterprise parsing structures via Tuple arrays
chat_prompt_blueprint = ChatPromptTemplate([
    ("system", "You are an expert technical advisor in the field of {domain}."),
    ("human", "Explain the concept of {topic} in clear and simple terms.")
])

# Injecting local system variables across multiple role locations concurrently
formatted_payload = chat_prompt_blueprint.format_messages(
    domain="Cloud Systems Engineering",
    topic="Kubernetes Pod Autoscaling Management"
)

print(formatted_payload)
```
